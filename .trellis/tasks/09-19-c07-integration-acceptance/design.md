# C07 design

## D1. End-to-end evidence

Use C01 physical corpus and C02 desktop session entry. Run each profile separately, with explicit project routing and retained raw receipts. Probe success alone cannot pass the desktop journey. Compare engine direct results with displayed/normalized identities, order, approximate totals and continuation.

Use controlled delayed responses for request/save races, then test the connected read path. Test doubles prove ordering, not live-engine timing. Reset the synthetic corpus between mutation/freshness scenarios; no real vault is involved.

## D2. Performance and quality

Use the frozen parent D4/C01 manifest without altering budgets or corpus after seeing results. Interleave direct and adapter measurements to reduce machine-load bias; record both. Report median and nearest-rank p95, five cold and 30 warm samples per supported case. CJK, literal and paraphrase groups remain separate by engine and mode. Unsupported semantic features have no artificial zero recall.

Control fixtures exercise approximate counts, malformed JSON-requested text, nested paths, duplicate basenames, old query pages, slow note A/fast note B, save A/new typing B, long identifiers and 1/5 MiB notes. Performance targets apply only to meaningful measured cases; missing data remains incomplete. A counter-based request budget gives deterministic evidence in addition to noisy clocks.

## D3. Native verification and final decision

When separately authorized, inspect the actual Tauri window at the required sizes and zoom, perform keyboard/Chinese IME flows, and capture native evidence with environment/session details. A web viewport run may support layout development but does not prove WebView2 or native IME. Screen-reader acceptance records actual observed announcements rather than source attributes alone.

Measure the C01 large-note typing protocol explicitly: 30 committed edits per 1 MiB/5 MiB note, 10 each at beginning/middle/end, event-to-presented-updated-frame using the frozen trace method; p95 limits are respectively 50 ms and 100 ms. Record initial full-note read separately. Compare delivered YAML/UTF-8/newlines with C01 fixtures, and report any upstream normalization instead of claiming raw disk-byte preservation.

Publish one integration acceptance report linking child outputs and parent ACs. Passing this bounded read-only program does not pass G0-G7, authorize real-vault writes or release the application. Report existing stage-order failures independently.
